Torii Digital Portfolio · Project Blueprint

A portfolio that builds itself from an employee code.

Every Torii employee gets a public, animated portfolio at one shared URL. Type your employee code and you land on your page; if it's new, you create one, fill in the sections, and drag them into any order you like. Coding-profile stats are fetched automatically from the links you paste. This is the plan for how we build it — for your sign-off.

02

How the pieces fit

One Next.js codebase does everything: the pages you see, the API that talks to MongoDB, and the server-side fetchers that pull coding stats. No separate backend to run or secure.

Frontend

Rendered pages

  • The landing / code entry screen
  • The public portfolio at /{code}, server-rendered for instant load
  • The editor with per-section forms and drag-to-reorder
API layer

Route handlers

  • Create / read / update a portfolio by code
  • Fetch coding stats from a pasted profile URL
  • Refresh cached stats on demand
Data + fetchers

MongoDB & adapters

  • One portfolio document per employee code
  • A per-platform adapter (LeetCode, GitHub…) that normalizes stats
  • Stats are cached in the document so public views are fast
03

The data model

A single flexible document per employee. Every field is optional — the UI only renders what exists. sectionOrder is what powers the drag-to-reorder feature.

// MongoDB collection: portfolios  ·  keyed by employeeCode
{
  employeeCode: "0020",          // the only identifier
  name:         "Aarav Sharma",
  createdAt, updatedAt,

  sectionOrder: ["profile", "coding", "tech", "ai", "projects"],  // drag to reorder

  profile: {
    photoUrl, tagline, bio, location, resumeUrl,
    socials: [ { platform, url } ]
  },

  codingProfiles: [ {
    id, platform, profileUrl, username,
    stats: { /* normalized per platform — solved, rating, ranks… */ },
    lastFetchedAt, fetchStatus   // ok | stale | failed
  } ],

  technologies: [ { id, name, certification, verificationId } ],
  aiSkills:     [ { id, name, level, description, certification } ],
  projects:     [ { id, name, imageUrl, url, description, techStack: [] } ]
}
04

Section specifications

Five sections, each with an "+ Add" flow for repeatable items. All inputs optional. The editor form on the left mirrors the animated block that renders on the public page.

Section · Profile

Profile summary

  • Photo, tagline, short bio, location
  • Social links — add any number (LinkedIn, X, personal site…)
  • Resume — upload / link, shown as a download button
Section · Coding

Coding profiles

  • Add: platform + profile URL — that's all they type
  • We auto-fetch username, problems by difficulty, contests, ratings & ranks
  • Rendered as animated stat tiles per platform; add as many as they want
Section · Tech

Technologies

  • Add: name, certification, optional verification ID
  • Certified items get a verified badge with the ID
Section · AI

AI skills

  • Add: technology, level, description, related certification
  • Level renders as a proficiency meter
Section · Projects

Projects

  • Add: name, image, URL, description, tech stack
  • Rendered as interactive project cards with live links
Behavior

Structure control

  • A "Structure" panel lists all sections as draggable rows
  • Drag order is saved to sectionOrder and drives the live page
  • Empty sections are hidden automatically
05

Coding-profile fetchers

The core technical challenge. Each platform gets its own adapter that turns a profile URL into normalized stats. Reliability varies — official APIs are rock-solid; platforms without one need HTML scraping and will need occasional upkeep. I'm flagging that honestly up front.

PlatformWhat we pullMethodReliability
LeetCode Username, total solved, easy / medium / hard split, contests attended, rating, global & country rank GraphQL endpoint Medium · unofficial
GitHub Repos, stars, followers, contributions, top languages Official REST / GraphQL API High · official
Codeforces Current & max rating, rank, problems solved, contests Official public API High · official
CodeChef Rating, stars, global & country rank, problems solved HTML scrape Fragile · scrape
HackerRank Badges, skills, problems / points where public HTML scrape Fragile · scrape
GeeksforGeeks Coding score, problems solved, institute rank HTML scrape Fragile · scrape

Stats are fetched on save and cached in the document, so public pages never wait on a scrape. A per-profile refresh button re-pulls on demand, and failed fetches degrade gracefully — the tile still shows the username and a link.

Build roadmap

Polish on a demo profile, add the light verification gate, deploy, then hand out the single URL to all employees.
